# Laravel QZ Tray — Security & Code Quality Audit

**Repository:** `bitdreamit/laravel-qz-tray`
**Audited commit:** `4a2ed1b` ("uuid or bigint", main branch) — package version 1.2.0
**Audit date:** 2026-08-30
**Result:** 27 findings (5 critical, 7 high, 9 medium, 6 hardening) — **all fixed** in the applied v1.2.1 patch. Fully backward compatible; one additive migration.

> **How to apply the fixes**
> - Option A: `git am laravel-qz-tray-v1.2.1-fixes.patch` inside your repo (preserves the commit), or `git apply <file>` for a working-tree-only application.
> - Option B: replace your working copy with `laravel-qz-tray-fixed-v1.2.1.zip`.
> - After applying: `php artisan migrate` (adds `client_job_id`), then `php artisan qz:doctor` to verify the install.

## 1. Executive Summary

The package was reviewed line-by-line: the 745-line `QzSecurityController`, the service provider, all four console commands, both route files, both migrations, the config, the 852-line `smart-print.js` client, and all three Blade views. The 28 bugs documented in the repository's own `BUG_REPORT.md` (BUG-01 through BUG-28) were verified as genuinely fixed — this audit covers only what remained. The three most serious remaining problems were a working PHP signing script that gets published into the public web root, a print-job logging design that could never produce correct status data, and two XSS sinks left in the client library.

## 2. Scope & Method

**Files reviewed:** `src/QzTrayServiceProvider.php`, `src/Http/Controllers/QzSecurityController.php`, all `src/Console/Commands/*`, `routes/web.php`, `routes/api.php`, both database migrations, `config/qz-tray.php`, `resources/js/smart-print.js` (+ adapters), `resources/views/{default,smart,example}.blade.php`, `composer.json`, and the repository tree itself.

**Method:**

1. Manual line-by-line reading of every PHP and JS source file, with the existing `BUG_REPORT.md` used as a "do not re-report" list.
2. Targeted verification of suspicious spots: `git cat-file -s` confirmed the installers are 0-byte tracked files; grep confirmed `window.QZ_CONFIG` is never set by any shipped view; `node --check` run on all JS.
3. Every finding was reproduced logically against the actual code paths before being written up, then fixed in code with the fix cross-referenced by audit ID in comments.
4. Structural verification of the edited PHP (brace/paren balance, duplicate-method scan, header checks) plus `node --check` on all edited JS. A PHPUnit suite was authored to lock the fixes in; see §10 for its run instructions.

## 4. Critical Findings

### C1 — Signing sample script published to the public web root

**Severity:** Critical / Security
**Files:** `src/QzTrayServiceProvider.php` (`boot()`, `qz-assets` publish group), `resources/assets/signing/sign-message.php`

The `qz-assets` publish tag copied the **entire** `resources/assets` directory into `public/vendor/qz-tray/assets/`. That directory contains `signing/sign-message.php` — QZ Industries' sample signer, whose header literally warns that unauthorized signing gets organizations blacklisted for piracy. On any php-fpm host, a file under `public/` is **executable**, so after the documented `php artisan vendor:publish --tag=qz-assets` step, anyone on the internet could request:

```
https://your-app.test/vendor/qz-tray/assets/signing/sign-message.php?request=<anything>
```

and receive a valid SHA512 signature produced by the server's private key, with no session, no CSRF token, and no rate limiting beyond the web server's own limits. That silently defeats every protection on the real `/qz/sign` endpoint and enables forged QZ print sessions. Even if the relative `private-key.pem` lookup failed on some hosts, shipping a live signer into the web root is a time bomb waiting for a layout where the key is reachable.

**Fix applied:** publishing is now file-by-file (`publishableAssets()`), skipping every `*.php` file and the whole `signing/` folder. The samples remain readable inside `vendor/` for reference but can never land in the web root:

```php
// src/QzTrayServiceProvider.php (new)
if (strtolower($file->getExtension()) === 'php') {
    continue; // Never publish executable content to the web root
}
if (str_starts_with($relative, 'signing'.DIRECTORY_SEPARATOR)) {
    continue; // signing/ samples must never live under public/
}
```

**Upgrade note for existing installs:** if you already published assets before, delete `public/vendor/qz-tray/assets/signing/` manually once, then re-publish.

### C2 — Duplicate print-job rows / every job stuck at `pending`

**Severity:** Critical / Functional (printing core)
**Files:** `QzSecurityController::print()`, `smart-print.js::logPrintJob()`, new migration `2026_08_30_000001_add_client_job_id_to_qz_print_jobs_table.php`

The controller treated `POST /qz/print` as insert-only, but the client reports the **same job twice by design**: once when printing starts and again (same client-generated `job_id`) after `qz.print()` settles. The consequences differed only by PK type:

- **uuid mode (default):** the second insert hits a duplicate-primary-key error, the `catch` swallows it, and the row stays `pending` forever. `processed_at` was never set; `GET /qz/jobs` was permanently wrong.
- **bigint mode:** the second report inserted a **second row** — every successful print produced two history records, and `status` on both stayed `pending`.

`status` values `processing`/`completed`/`failed` existed in the schema but nothing in the entire system could ever set them.

**Fix applied (two halves):**

1. Server: `POST /qz/print` is now an **upsert**. In uuid mode an existing row with the same `id` is updated in place; in bigint mode a new additive nullable `client_job_id` column (unique-indexed) gives the same idempotency. `processed_at` is stamped the first time a terminal status arrives and can never regress.
2. Client: `smart-print.js` now reports the real lifecycle — `processing` before `qz.print()`, then `completed` (or `failed` + `error_message`) after it settles.
3. New endpoint: `PATCH /qz/jobs/{id}` for dedicated status updates, with the same ownership scoping as cancel (see C4). `GET /qz/jobs?status=...` accepts a comma-separated status filter.

```php
// QzSecurityController::print() — upsert core (v1.2.1)
if ($existing) {
    DB::table('qz_print_jobs')->where('id', $existing->id)->update($base + [
        'status' => $status ?? $existing->status,
        'processed_at' => in_array($status, ['completed','failed','cancelled'], true)
            ? ($existing->processed_at ?? now())
            : $existing->processed_at,
    ]);
    $jobId = (string) $existing->id;
} else {
    // ... insert with client_job_id ...
}
```

**Upgrade note:** run `php artisan migrate`. Existing rows get `client_job_id = NULL` and keep working.

### C3 — XSS in the printer-selection modal and the failed-queue UI

**Severity:** Critical / Security
**File:** `resources/js/smart-print.js` (old lines ~615 and ~725)

BUG-01 fixed this exact bug class in `smart.blade.php` — but two sinks of the same kind remained in the shared library everyone actually loads:

```js
// OLD — printer names from the OS interpolated unescaped
`<button data-printer="${p}" ...>${p}</button>`           // innerHTML

// OLD — job.url (caller/user-controlled) injected into innerHTML
li.innerHTML = `Failed: ${job.type} — ${job.url || 'Raw Data'} `;
```

Printer names can originate from a malicious network share (e.g. `\\evil\share<img onerror=...>`), and `job.url` comes straight from `data-qz-print` attributes, which are frequently built from user-generated content. Either sink executes JavaScript in the host page's session — same-origin, CSRF tokens and all.

**Fix applied:** the modal is built entirely through the DOM API (`createElement` + `textContent` + `dataset`), and the queue rows now use `textContent`. An `escapeHtml()` helper was added for the remaining string-interpolation cases. Verified with `node --check`.

### C4 — IDOR: any session could cancel any print job

**Severity:** Critical / Security
**File:** `QzSecurityController::cancelJob()`

`cancelJob()` looked the job up by id alone — no ownership check of any kind. Under the `web` middleware that means any visitor (even anonymous, via a session) could cancel any job; in bigint mode ids are sequential, so cancellation of other tenants' or other workstations' jobs was trivially scriptable. The same weakness applied to job status changes once C2 introduced them, so both endpoints share the fix.

**Fix applied:** both `cancelJob()` and the new `updateJobStatus()` scope the lookup to identities owned by the requester — the authenticated user (id **and** type pair, matching `jobs()`) or the request's device UUID. A job owned by someone else returns 404 without leaking its existence:

```php
$job = DB::table('qz_print_jobs')
    ->where('id', $id)
    ->where(function ($query) use ($user, $deviceId) {
        if ($user) {
            $query->where(function ($q) use ($user) {
                $q->where('user_id', (string) $user->getAuthIdentifier())
                  ->where('user_type', get_class($user));
            });
        }
        if ($deviceId) { $query->orWhere('device_id', $deviceId); }
        if (! $user && ! $deviceId) { $query->whereRaw('1 = 0'); }
    })
    ->first();
```

### C5 — Certificate auto-generation race and unhandled failure

**Severity:** Critical / Reliability (affects all signing)
**File:** `QzTrayServiceProvider::autoGenerateCertificate()`

Two problems shared one function. First, it runs during `boot()` on every request while the certificate is missing. Two concurrent FPM workers both saw "missing", both generated **different** key pairs, and their `file_put_contents` calls interleaved — leaving a certificate from worker A paired with a private key from worker B on disk. Every signature from that point failed until someone regenerated manually, and the failure mode (QZ Tray rejecting signatures) gives no hint about the cause. Second, there was no error handling: on read-only storage (Docker images, Lambda snapshots, immutable deploys) the write failed with warnings/exceptions during boot on every request when `auto_generate_cert` was enabled.

**Fix applied:**

1. Generation now runs under an atomic `Cache::lock('qz-tray:cert-generation', 30)` (degrading gracefully when no lock store exists), with a double-check after acquisition.
2. Files are written to temp files in the same directory and moved into place with `rename()` — atomic on POSIX, so a request mid-generation sees either the old pair or the complete new pair, never a mix.
3. The whole routine is wrapped in try/catch: a failure now logs one clear error (`[QZ Tray] Automatic certificate generation failed: ...`) instead of crashing boot; every OpenSSL call checks its return and includes `openssl_error_string()` in the message.

## 5. High-Severity Findings

### H1 — 0-byte installer files served as real downloads

`resources/installers/qz-tray-windows.exe`, `qz-tray-macos.pkg` and `qz-tray-linux.deb` were tracked in git as **empty files** (`git cat-file -s` → 0). `installer()` used `is_file()` as its gate, which passes for empty files, so users who clicked "download the installer" received a 0-byte `.exe` that silently corrupted their install attempt. The endpoint now requires `filesize() > 0` and otherwise falls through to the official-download JSON (existing behavior). The placeholders were removed from git and replaced by `docs/README.md` explaining how to drop real binaries in.

### H2 — Hardcoded `/qz/` prefix everywhere in the client

`smart-print.js` hardcoded `/qz/certificate`, `/qz/sign`, `/qz/printer`, `/qz/print`; `default.blade.php` did the same — yet `config('qz-tray.routes.prefix')` is configurable. Changing the prefix silently broke certificate retrieval (QZ Tray connection fails), signing, printer memory and job logging. The client now resolves endpoints through `window.QZ_CONFIG` (a `prefix` or per-endpoint absolute URLs), and both shipped views bridge the server config into `window.QZ_CONFIG` automatically. Host apps embedding the JS by hand can set the same object before including it.

### H3 — Apache rejects the encoded page path (`%2F`) → printer memory 404s

`restorePrinter()` sent the page path as a URL-encoded path segment: `fetch('/qz/printer/' + encodeURIComponent(pathKey()))`. `encodeURIComponent('/invoices/page')` produces `%2Finvoices%2Fpage`, and Apache's default `AllowEncodedSlashes Off` rejects any `%2F` with a 404. Every Apache-hosted install therefore silently lost server-side printer restore. A query-param route `GET /qz/printer?path=...` was added (the segment route remains for compatibility), and the client now uses it. Both paths share one implementation (`getPrinterByQuery` delegates to `getPrinter`).

### H4 — Printer-preference endpoints crashed before migration

`print()`, `jobs()` and `cancelJob()` checked `Schema::hasTable(...)` and degraded gracefully — but `setPrinter()`, `getPrinter()` and `clearCache()` hit `\DB::table('qz_printer_preferences')` directly, producing a raw `QueryException` 500 for anyone who installed the package and hit the endpoints before `php artisan migrate`. All three now return a consistent 503 JSON with a `Run: php artisan migrate` message, matching the style of the other endpoints.

### H5 — `X-Device-Id` header written to a uuid column without validation

In `print()`, the device id came straight from the header:

```php
$deviceId = $request->header('X-Device-Id') ?? $request->input('device_id'); // OLD
```

`resolveIdentities()` validates the header against a UUID regex, but `print()` did not — and `device_id` is a native `uuid` column. Any non-UUID garbage in the header made the INSERT throw; the catch block downgraded `db_logged` to false and emitted a warning log on **every** print, so job logging silently stopped while printing still worked. The header is now validated exactly like `resolveIdentities()` does, falling back to the already-validated body value, else `null`. A regression test (`test_invalid_device_id_header_does_not_break_logging`) locks this in.

### H6 — `connectQZ()` concurrent-call race wrongly pushed jobs offline

The old concurrency guard waited a blind 200 ms and then checked `qz.websocket.isActive()`. A real QZ handshake takes ~1 s, so any caller arriving during a slow connect got `false`, and `processQueue()` routed its job to `offlineBuffer()` — the print appeared "failed/offline", was persisted to the offline queue, and later retried as a **duplicate print** after the connection actually succeeded. All callers now share one in-flight promise (`state.connectPromise`), so the second caller simply awaits the same attempt. Also, `qz.printers.find()` throwing on a printer-less Tray no longer fakes a connection failure.

### H7 — `qz:launch` protocol dialog every ~10 seconds

The 10-second auto-reconnect loop retried `connectQZ(1)`, and each failed attempt triggered `launchQZProtocol()` — a hidden iframe navigating to `qz:launch`. On machines without QZ Tray, Firefox shows a native "open with application?" dialog **each time**, i.e. roughly every 10–20 seconds for as long as the tab is open. Protocol launches are now capped at 2 per page load; reconnects after that are silent. A regression guard: `state.launchAttempts`.

## 6. Medium-Severity Findings

### M1 — `/qz/status` reported version `1.0.0` while composer said `1.2.0`

Hardcoded strings drift. The version is now a single source of truth — `QzTrayServiceProvider::VERSION` (`1.2.1`) — consumed by the status endpoint and kept in lockstep with git tags and the new `CHANGELOG.md`. `composer.json` no longer carries a `version` field at all (P5): releases are tags, which is the Packagist-recommended workflow.

### M2 — `testPdf()` threw a TypeError whenever DomPDF was installed

The method declared `: \Illuminate\Http\Response`, but DomPDF's `stream()` returns `Symfony\Component\HttpFoundation\StreamedResponse` — a **sibling**, not a subclass. So the one code path that only activates when DomPDF *is* installed failed at runtime with a return-type error; without DomPDF the endpoint worked, which is why it survived testing. Widened to the Symfony parent type, which both return paths satisfy.

### M3 — `jobs()` ignores the session identity for anonymous callers

`print()` stores the job but the queue query scopes by user **or** device only; an anonymous kiosk without a device id can log jobs it can never see. This is a design gap rather than a defect in current default flows (smart-print.js always sends a device id), so it is documented instead of silently changed: anonymous session-scoped queues would need a `session_id` column, which is a schema decision left to v1.3 (see §9).

### M4 — Tenant id accepted 21+ digit numbers → 500 instead of 422

`isValidTenantId()` in bigint mode used `^\d+$` with no upper bound. `'99999999999999999999'` passed validation, then the INSERT blew up with an out-of-range error — a clean 422 became a 500 on `setPrinter()`. Numeric ids are now bounded to the unsigned BIGINT range (`\d{1,20}` plus a string comparison against `18446744073709551615`, no bcmath dependency). Test: `test_tenant_id_out_of_bigint_range_is_rejected`.

### M5 — Dead config: `hotkey.*`, `websocket.*`, `fallback.*` never reached the client

The PHP config exposed a hotkey combination, WebSocket retry settings and fallback switches that nothing consumed: the JS hardcoded `ctrl+shift+p`, and no view ever set `window.QZ_CONFIG`. The config bridge now ships the real values (`prefix`, `uuidVersion`, `serverSync`, `hotkey.enabled`, `hotkey.combination`) into both views, and the JS honors them — `server_sync` was added as an explicit config key (`QZ_SERVER_SYNC`) instead of the previous opt-out-only JS flag. The `websocket.*` block remains server-irrelevant (QZ Tray's WS settings live client-side in QZ Tray itself) and is flagged for removal in v2.

### M6 — `rememberPrinter()` POSTed on every print

`printQZ()` calls `rememberPrinter()` on every job, and the old code fired a `POST /qz/printer` each time — four identical writes for four receipts on one page. The sync now fires only when the effective (scope, printer) pair actually changes (`state._lastSyncedKey`), cutting request volume dramatically on receipt-heavy pages without changing behavior.

### M7 — Auto-print elements were scanned exactly once

`bind()` ran `document.querySelectorAll('[data-qz-auto-print]')` at DOMContentLoaded, so anything injected later — Turbo/Inertia navigation, modals, AJAX-loaded panels — never auto-printed. `bind()` now accepts a root element and is exported as `SmartPrint.bind(root)`; additionally, an opt-in MutationObserver (`window.QZ_CONFIG.observeDom = true`) queues auto-print nodes as they appear. The delegated click handler is registered exactly once regardless of how many times `bind()` is called.

### M9 — `qz_print_jobs` grew forever

Preferences had `qz:prune-preferences`, but the jobs table — one row per print attempt — had no lifecycle at all. New `qz:prune-jobs` command with `--older-than=30`, `--status=`, `--keep=N` (preserve the newest N regardless of age) and `--dry-run`, ready for the scheduler:

```
$schedule->command('qz:prune-jobs --older-than=30')->daily();
```

### M12 — `POST /qz/generate` lets anyone rotate the keypair (when enabled)

Disabled by default, but the "enabled" story is dangerous: with `allow_public_cert_generate = true` any visitor could regenerate the certificate — a DoS button that also silently invalidates every workstation's trust with no authentication gate. The code keeps working (compat), but the config comment now states the risk explicitly and recommends `auth` middleware via route middleware overrides. Longer term this endpoint should either require auth by construction or be removed in v2 (§9).

## 8. New Features Delivered (all additive, non-breaking)

1. **`PATCH /qz/jobs/{id}`** — dedicated lifecycle endpoint (`processing` / `completed` / `failed` + `error_message`), ownership-scoped; registered on both web and API surfaces (`qz.jobs.status`, `api.qz.jobs.status`).
2. **`GET /qz/printer?path=...`** — Apache-safe printer-memory reads (H3).
3. **`client_job_id` migration** — idempotent job logging for bigint installs (C2).
4. **Eloquent models** — `QzPrintJob` and `QzPrinterPreference` with `forTenant()`, `forDevice()`, `pending()`, `stale()` scopes and config-aware key types, so host apps integrate instead of re-implementing raw queries.
5. **Laravel events** — `PrintJobLogged` and `PrintJobStatusUpdated`, fired from `print()`, `updateJobStatus()` and `cancelJob()`; host apps can mirror print activity into their own audit trails.
6. **`qz:doctor`** — one-command health check: PHP/OpenSSL, certificate existence + expiry (warns under 30 days), key permissions, DB tables, `client_job_id` presence, config sanity; exit code is CI-friendly.
7. **`qz:prune-jobs`** — job-table retention (M9).
8. **`QZ_CONFIG` bridge + configurable hotkey** — server config finally drives the client (H2/M5).
9. **Test suite + CI** — the package's first executable safety net (P1/P2).

## 9. Roadmap (recommended, not in v1.2.1)

Kept out deliberately because they change structure or are product decisions:

1. **Split the controller (v2.0).** One 745-line controller handling certificates, signing, preferences, jobs, installers and demos invites regressions like C2/H5. Extract `CertificateService`, `PrintJobService`, `PrinterPreferenceService` + Form Requests, keeping the same routes/behavior. The audit IDs in comments mark every touched method, which maps the future extraction surface.
2. **Gate the demo routes.** `/qz/test`, `/qz/smart`, `/qz/test/pdf` register unconditionally in production; add `routes.demo` config (default off) in v1.3.
3. **Session-scoped anonymous queues (M3).** Add a `session_id` column or reuse `identity_value` so anonymous kiosks can read their own queue.
4. **Remove `POST /qz/generate`** or require auth by construction (M12).
5. **Drop `websocket.*` / `fallback.*` dead config** in the next minor (M5 leftovers).
6. **Docs split + `SECURITY.md` + `CONTRIBUTING.md`**; add SmartPrint `.d.ts` type definitions; consider Git LFS or release attachments if real installer binaries are ever shipped.
7. **Promote the Laravel 13 CI canary** to the main matrix once the Laravel 13 / Testbench 11 pair is stable, and tighten PHPStan from the level-5 baseline.

## 10. Verification & Limitations

**Verified in this environment:**

- `node --check` passes on every edited JS file (`smart-print.js`, adapters, switcher, status).
- Structural PHP checks pass on every edited/new file: balanced braces/parens outside strings and comments, no duplicate method names, no stray `?>`, correct `<?php` headers (`scripts/php_sanity_check.py`).
- `composer.json` parses as valid JSON.
- Cover-level behavior of each fix was re-derived against the edited sources (e.g. upsert path, ownership scoping, publish filter) and each carries an `AUDIT` comment tag for greppability.
- The complete change set is a single git commit on top of `4a2ed1b`; `git diff HEAD~1` is the review surface, and `git format-patch -1` produced the deliverable patch.

**Limitations to be aware of:**

- The audit environment has no PHP CLI, so `composer install && composer test` could not be executed here.
